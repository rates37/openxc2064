# Technology Mapping & Packing (XC2064)

This document explains the logic transformation passes used in the Mapping and Packing phase of the OpenXC2064 synthesis toolchain. These algorithms convert generic synthesised 1-bit-wide logic (AND, OR, XOR, NOT, etc.) into the physical hardware structures specific to the Xilinx XC2064 FPGA.

## Architectural Details/Constraints of the XC2064

The XC2064 itself consists of a generic matrix of interconnected configurable logic blocks (CLBs) and periphery I/O blocks (IOBs). For full details, consult the [Xilinx XC2064 datasheet](https://datasheet4u.com/datasheets/Xilinx/XC2064/625540). The key components that are of interest here are primarily:

- 64 CLBs arranged in an 8x8 grid
- 60 IOBs along the perimeter

Each CLB contains a fixed amount of logic resources configurable via static RAM (SRAM) memory arrays. A single CLB is mathematically constrained to offer:

- 4 General Purpose Inputs (nets), labeled `A`, `B`, `C`, `D`.
- 2 3-input LUTs (Look-Up Tables), evaluating up to two independent 3-variable Boolean equations. Look-Up Tables map their input states as an index pointing to an SRAM configuration bit (an 8-bit truth table for 3 variables).
- 1 D-Type Flip-Flop (DFF) for sequential state storage.
- 1 Clock Input (net), labeled `K`.
- 2 Outputs (nets), labeled `X`, `Y`.

Note: the CLBs can be configured to offer a single 4-input LUT instead of two 3-input LUTs. This is not yet supported, as the MVP will target strictly the 2x 3-input LUT CLB configuration.

## 1. Technology Mapper (`TechnologyMapper`)

The `TechnologyMapper` interface defines the phase translating the arbitrary-depth computational graph of Boolean primitives generated by `LoweringPass` into an equivalent physical network built entirely out of $K$-input LUTs (and DFFs). For the XC2064, $K \le 4$ (or 3, under the MVP constraints).

### Algorithm: Greedy Cut Enumeration (`GreedyMapper`)

The `GreedyMapper` implementation subclasses the base `TechnologyMapper` class to dynamically formulate optimal sub-networks. Each `LUT` stores the entire truth table for its configuration in a 8-bit integer (bitset), where the $i$-th bit is the output of the LUT for the $i$-th input combination (i.e., the minterm $\text{m}_i$).

The Greedy mapping algorithm is as follows:

1. Traversal: Iterates through the existing netlist backwards, originating from output boundary gates or intermediate DFF logic constraints.
2. K-Feasible Cuts: When a gate is evaluated, the mapper traces the logic tree propagating backwards (the Fan-in Cone) gathering dependent input nets. It continues traversing backwards until the number of unique input nets in the cone hits exactly $K=3$. The subgraph evaluated constitutes a generic `Cut`.
3. Truth Table Extraction: Once a cut is isolated, we instantiate a `LUT` object. By exhaustively evaluating $2^K = 8$ permutations of inputs into the captured Boolean network cut and recording the boolean output evaluation $Q$, we precompute an 8-bit literal integer that explicitly encodes the Truth Table function.
4. Graph Replacement: Remove the mapped Boolean subgraph completely and stitch the singular equivalent `LUT` node in-place into the broader network graph, driving the original subset output net.

This process loops over the unmapped regions until the entire graph is built from LUTs, DFFs, and Input port boundaries.

### Primitive Bypass (Constants & DFFs)

During the backward traversal algorithm, the mapper intercepts hard-coded structural nodes before they can trigger greedy `LUT` clustering:

- `Constant` Nodes: If a hardcoded binary value (e.g., `1'b0` tied to a `cin` pin) is encountered, it is cloned directly into the mapped netlist. This ensures constants remain free, lightweight primitives that simply supply a high/low voltage, rather than wasting an entire 3-input configurable `LUT` cell just to evaluate a static 0 or 1.
- `DFF` Nodes: When the backward pass hits a D-Flip-Flop (the register storing state from the previous clock cycle), the traversal terminates for that path. The `DFF` is cloned into the new netlist, and its data input (`D`) becomes a new target for the mapping algorithm to resolve in a subsequent pass. This naturally fragments synchronous designs into combinatorial sub-graphs separated/interconnected by registers.

### Example: K-Feasible Truth Table Extraction

Suppose the synthesiser previously formulated the logical condition `Q = (A AND B) OR C`.
The `GreedyMapper` encounters `OR` driving `Q`. Tracing backward:

- It discovers inputs: the `AND` gate, and the `C` input net. Total unique inputs `(A, B, C) = 3`.
- Since $3 \le K=3$, this entire subset `(A AND B) OR C` is consumed within a single K-feasible cut

To configure the LUT, the mapper loops through $2^3 = 8$ index variables:

- `CBA = 000` -> Result $Q=0$
- `CBA = 001` -> Result $Q=0$
- `CBA = 010` -> Result $Q=0$
- `CBA = 011` -> Result $Q=1$
- `CBA = 100` -> Result $Q=1$
- `CBA = 101` -> Result $Q=1$
- `CBA = 110` -> Result $Q=1$
- `CBA = 111` -> Result $Q=1$

These binary variables literally synthesise down into an 8-bit numeric integer `Truth Table`. The arbitrary combinatorial `AND`/`OR` gates vanish, and are substituted into the netlist by `LUT(inputs=[A,B,C], truth_table=0b11111000)`.
